# Дорожная карта и отложенные решения

## Блокирующие решения (нужны до продакшена)

1. **AI-контур под 152-ФЗ.** OCR, речь-в-текст и разбор естественного языка
   обрабатывают персональные медданные — зарубежные облачные API исключены.
   Выбор: РФ-облако (Yandex / VK / Sber) либо self-hosted модели на РФ-инфраструктуре.
   Точки подключения уже готовы: `services/ocr.py`, `services/stt.py`, `services/nlp.py`.
2. **Юридическое заключение** о границе «не медизделие» — влияет на то, можно ли
   включать перекрёстные проверки аллергий по фарм-группам и как оформлять согласия.

## Готово к подключению (интерфейсы есть, тело — заглушка)

- OCR + извлечение значений — `services/ocr.py`
- Речь-в-текст — `services/stt.py`
- Разбор естественного языка для напоминаний — `services/nlp.py`
- Проверка аллергий: MVP — точное совпадение/группа; этап 2 — перекрёстные реакции

## Требования, зафиксированные, но ещё не реализованные

- **В духе Toki (следующая волна)**: триггеры (следить за условием и создавать задачу
  — напр. PSA пересёк порог у любого пациента); эскалация просроченных напоминаний
  (push → повторный push → «позвонить»); мультимодальный захват (фото/скрин направления
  → событие/задача); дневные и недельные сводки; конфликты в расписании.
- **Протокол под реальный ЕМИАС**: сейчас поля близки к амбулаторной карте, но
  разметку нужно выверить под фактический экран ЕМИАС (заказчик пришлёт образец).
  Возможна прямая интеграция через API, если она доступна; иначе — копирование
  по блокам (уже сделано).
- **Google Календарь**: импорт приёмов через OAuth (роутер `/calendar`) — кнопка
  «Подключить» в разделе «Ещё» уже есть.
- **Push-уведомления** о распознавании (успех / нужна пересъёмка) — часть основного
  цикла, нужен сервис пушей с MVP.
- **Печатная выписка (A4 / PDF)** и экспорт выписки одного пациента.
- **Асинхронный конвейер распознавания**: врач фотографирует и продолжает приём,
  значения появляются в очереди подтверждения позже.
- **Устойчивая загрузка при потере сети**: съёмка офлайн → локальная очередь → отправка.
- **Словарь параметров** как справочник в БД (сейчас коды заданы в наблюдениях).
  Основа — файл `словарь_параметров_вторая_память.xlsx`.
- **Версионируемый справочник порогов** клинрекомендаций (редакционный процесс).
- **Справочник препаратов/МНН** (ГРЛС/РЛС) для проверки аллергий.

## Инфраструктура продакшена

- Замена SQLite → PostgreSQL (только `DATABASE_URL`, схема не меняется).
- РФ-хостинг, шифрование, изоляция БД каждого врача, ежедневные бэкапы,
  экспорт по одной кнопке, полный append-only аудит (модель `AuditEvent` уже есть).
- Реальная аутентификация врача (PIN → хеш, вход по SMS/email при новом устройстве).

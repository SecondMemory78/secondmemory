# ADR-0002. Справочные данные — версионируемые, не хардкод

## Контекст
Врач предоставил справочник v4 (279 параметров, МКБ-10, препараты, аллергии) по
официальным источникам РФ. Данные меняются (новые версии МКБ, ЕСКЛП, клинреком).

## Решение
- Справочники храним как версионируемые данные (`backend/app/reference/*.json`) с блоком
  `version` (источник, дата, примечание). Прообраз схемы врача: DictionaryVersion/SourceRegistry.
- В MVP грузим срез под урологию (МКБ ~553 кода из 15 000; параметры 279; группы аллергий 124).
  Полные таблицы (весь МКБ, ЕСКЛП) подключаем при масштабировании.
- Ничего не перезаписываем без новой версии. Диагнозы у пациента хранят код + версию МКБ.

## Статус
Принято. Извлечение выполнено (тикет T1).

## Дополнение (v4 целиком)
По просьбе заказчика в фундамент занесён ВЕСЬ словарь, не только урология: полный
МКБ-10 (15038), ЕСКЛП (7563), препараты/бренды/компоненты, классификации, перекрёстные
реакции, скрытые аллергены, фенотипы и т.д. Полный дамп каждого листа — в
`backend/app/reference/full/*.json` (формат columns/rows), карта — `manifest.json`.
Курированные (чистые ключи) — для кода: parameters, icd_urology, drugs, drug_aliases,
drug_components, allergy_groups, cross_reactions, hidden_allergens, phenotypes,
classifications, substitution_rules.

Объём сырых JSON ~43 МБ. В продакшене эти справочники переезжают в версионируемые
таблицы БД (по схеме врача: DictionaryVersion/SourceRegistry/ICDCode/DrugConcept…),
а не поставляются как raw-JSON. Загрузка — один раз, поиск — по индексам.

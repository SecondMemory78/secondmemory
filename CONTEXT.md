# CONTEXT.md — общий язык проекта «Вторая память»

Этот файл — источник правды по терминологии и правилам. Код, имена переменных,
таблицы и разговоры держим в этих терминах.

## Что это
Клиническая память врача: «карманный ординатор», который **помнит, напоминает,
записывает и вносит** — но **решает всегда врач**. Не система принятия врачебных
решений, не медицинское изделие.

MVP — урология. Архитектура закладывается под все специальности: при регистрации
врач выбирает специальность, справочники подключаются по специальности.

## Глоссарий (доменные термины)
- **Врач (Doctor)** — владелец аккаунта и всех своих данных. MVP: один врач — своя база.
- **Пациент (Patient)** — карточка человека у конкретного врача.
- **Наблюдение (Observation)** — одно измерение показателя во времени (временной ряд,
  не документ). Пример: `psa_total = 4.82 нг/мл, 2026-03-09`.
- **Показатель (Parameter)** — каноническое определение из справочника: код, единица,
  синонимы, порог, приоритет. См. `backend/app/reference/parameters.json`.
- **Визит (Encounter)** — одно посещение. Связывает приём + внесённые в этот день
  наблюдения, назначения, заметки, протокол, документы. *(вводится, см. ADR-0004)*
- **Приём (Appointment)** — запись в календаре на дату/время (первичный/повторный).
- **Диагноз пациента (PatientDiagnosis)** — код МКБ-10 + версия + формулировка врача +
  статус (активный/снят) + дата. У пациента их **несколько**; один помечен «основной».
- **Задача / Напоминание (Reminder)** — дело врача (Todoist/Toki-стиль): срок, повтор,
  приоритет, раздел (#тег). Может быть привязано к пациенту.
- **Триггер (Trigger)** — сохранённое условие слежения; заводит контроль при пересечении порога.
- **Протокол осмотра (VisitProtocol)** — структурированные поля как в ЕМИАС (жалобы,
  анамнез, объективно, локальный статус, диагноз, рекомендации).
- **Справочник (Reference)** — версионируемые официальные данные РФ (параметры, МКБ-10,
  препараты, аллергии). Никогда не хардкодим; храним с версией и источником.
- **Агент команд (Assistant)** — превращает фразу (голос/текст) в действие: приём,
  задача, заметка, запись в карту.

## Роли
- **doctor** — только свои пациенты и медданные.
- **support** — только чаты поддержки; медданных не видит.
- **admin** — аналитика + управление врачами + чаты поддержки; **карту пациента открыть
  НЕ может** (152-ФЗ, by design).

## Инварианты безопасности (нарушать нельзя)
1. **Никаких автозамен лекарств.** `auto_substitution_allowed = FALSE`,
   `physician_review_required = TRUE` всегда. Система предлагает/предупреждает — не решает.
2. **Перекрёстная реактивность не по классу, а по структуре** (боковая R1-цепь). Никаких
   упрощённых «пенициллин → любой цефалоспорин».
3. **Комбинированные препараты раскладываются на компоненты**; аллергия оценивается
   по каждому компоненту и скрытым компонентам (PEG, полисорбат и т.п.).
4. **Тошнота/ЖКТ ≠ аллергия.** Фенотип реакции фиксируется отдельно.
5. **OCR-значения попадают в карту только после подтверждения врачом** (статус pending).
6. **Аудит только на добавление** (append-only). Историю диагнозов не затираем.
7. **Фото после распознавания не храним** — только распознанный текст.
8. **Справочные данные версионируются**; ничего не перезаписываем без новой версии.

## Определение «готово»
Фича готова, когда: есть тест (зелёный) **и** прокликано вручную **и** работает гладко.

## Не-цели MVP
Мультиврач/клиника с общим доступом; полный МКБ вне урологии в UI; автоподбор терапии;
офлайн-режим (OCR/агент требуют сервера).

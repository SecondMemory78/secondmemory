# Вторая память

Клиническая память врача: система помнит всё о пациенте и показывает динамику.
**Врач принимает решения — система только организует память и подсвечивает, где нужно внимание.**
Это не система принятия врачебных решений и не медицинское изделие.

Концепция: **карманный продвинутый диктофон для врача** — с календарём, умной
записью дел (в духе Todoist/Toki) и памятью по каждому пациенту.
MVP-специальность: урология.





## Безопасность (реализовано)
- **Security-заголовки** на всех ответах (nosniff, X-Frame-Options: DENY, CSP frame-ancestors,
  Referrer-Policy, Permissions-Policy). HSTS — за https (`SECURE_HSTS=1`). Полный CSP HTML-страницы
  задаётся фронтом/nginx в проде.
- **Анти-брутфорс входа**: лимит попыток пароля (10/5 мин) и кода из письма (5/10 мин),
  сброс при успехе. In-memory; для кластера — Redis.
- **Шифрование чувствительных полей** (ФИО, телефон, тексты заметок, текст бланка согласия):
  прозрачно через тип-декоратор — в БД шифротекст (Fernet/AES), в приложении открытый текст.
  Ключ — `FIELD_KEY` из окружения, ВНЕ базы; в dev есть детерминированный ключ, **в проде задать свой
  и бэкапить отдельно** (потеря ключа = потеря данных). Поиск по фамилии работает (фильтрация
  расшифрованных значений на сервере). Старые записи с открытым текстом читаются как есть (плавная миграция).
- **Row-Level Security (RLS) на уровне БД** (Postgres): второй слой к коду — врач видит
  только своих даже если в коде забыт фильтр по doctor_id (проверено на живом Postgres:
  SELECT * возвращает только своих; чужого явно не достать; дочерние таблицы через подзапрос).
  Требования к деплою: приложение подключается к БД под **непривилегированной ролью**
  (владелец/суперпользователь обходит RLS), политики включаются автоматически при старте.
  Админ-контекст (x-admin-token) использует bypass для сводной аналитики.
- **Токены сессий хранятся хешами** (sha256) — дамп БД не выдаёт рабочих токенов.
- **Production-guard**: в проде (AUTH_OPTIONAL=0) приложение не стартует с дефолтными
  ADMIN_TOKEN/FIELD_KEY/CORS — защита от человеческого фактора.
- **Самопроверка ключа шифрования при старте**: отпечаток FIELD_KEY хранится в БД;
  при несовпадении (подмена/потеря ключа) прод не стартует — вместо «каши» явная ошибка.
- **CORS** ограничивается переменной CORS_ORIGINS (в dev — открыт).
- **Уведомление поддержки**: новое обращение врача уходит письмом на SUPPORT_EMAIL
  (если задан SMTP; иначе тихо, обращение всё равно сохраняется).
- **Минимизация**: фото документов/бланков не храним — только распознанный текст.
- **Аудит** (append-only) и журнал доступа; согласие 152-ФЗ как жёсткий барьер.

Дальнейшее (к деплою/юристу): TLS+HSTS на проде, приватная БД+VPN, сертифицированные ФСТЭК
средства для УЗ-1/2, шифрованные бэкапы, план реагирования и уведомление РКН, пентест.



## Web Push (уведомления на телефон)
Работает на Android/desktop и iPhone (iOS 16.4+, при добавлении на экран «Домой»).
Требуется HTTPS-домен в проде. Настройка ключей VAPID:
1. Сгенерировать пару: `python -m py_vapid --gen` (или онлайн-генератор VAPID).
2. Прописать в .env: VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, VAPID_SUBJECT_EMAIL.
3. Публичный ключ фронт берёт сам через /api/push/vapid-key.
Иконки (public/icon-192,512, apple-touch-icon, badge-96) — временные (буква «В» на синем),
заменяются на фирменные без изменений кода. Здоровье доставки — в админке (/api/admin/push/health).

## CSP фронтенда (nginx, к деплою)
Шрифты и иконки теперь локальные (в сборке), внешних CDN нет. Рекомендуемый заголовок
для статики фронта на nginx:
`Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: blob:; connect-src 'self'`
('unsafe-inline' в style-src нужен из-за инлайновых стилей React; script-src остаётся строгим.)

## PostgreSQL через PgAdmin4 (нормальная БД)

1. **В PgAdmin4** создай роль и базу:
   - Login/Group Role → `second_memory` (вкладка Definition — задай пароль).
   - Databases → Create → Database `second_memory`, Owner: `second_memory`.
2. **Укажи адрес БД** (файл `backend/.env` или переменная окружения):
   ```
   DATABASE_URL=postgresql://second_memory:ПАРОЛЬ@localhost:5432/second_memory
   ```
   PowerShell на время сессии: `$env:DATABASE_URL="postgresql://second_memory:ПАРОЛЬ@localhost:5432/second_memory"`
3. **Зависимости**: `pip install -r requirements.txt` (уже включает `alembic` и `psycopg2-binary`).
4. **Создай схему миграцией** (из папки `backend/`):
   ```
   alembic upgrade head
   ```
5. **Демо-данные**: `python -m app.seed` (или кнопка «Посмотреть демо» в приложении).
6. **Запуск**: `uvicorn app.main:app --reload`.

**Важно про схему.** На Postgres таблицы и колонки ведёт **только Alembic**
(`create_all` там намеренно отключён — иначе новые поля не добавляются и возникает
«no such column»). После любого изменения моделей:
```
alembic revision --autogenerate -m "что изменил"
alembic upgrade head
```
SQLite для разработки продолжает работать как раньше (таблицы создаются сами;
`python -m app.reset_db` пересоздаёт dev-файл).

### Ошибка «no such column: doctor.email»
Означает, что локальный `second_memory.db` создан до изменения моделей (в dev
`create_all` не добавляет новые колонки в существующие таблицы). Лечится
пересозданием dev-БД: останови uvicorn и выполни `python -m app.reset_db`
(удалит старый файл, создаст таблицы по текущим моделям, засеет демо).
В проде схему ведём миграциями (Alembic), а не пересозданием.

## Разработка (методология)
Работаем по принципам Мэтта Покока (mattpocock/skills): общий язык, тесты-вперёд, глубокие
модули, маленькие шаги.
- `CONTEXT.md` — общий язык: глоссарий, доменная модель, инварианты безопасности.
- `docs/adr/` — записи ключевых решений (авторизация, версии справочников, аллергобезопасность,
  визит, мультидиагноз).
- `docs/TICKETS.md` — карта работ «крепкой базы» с зависимостями.
- `backend/app/reference/` — версионируемые справочники врача по официальным источникам РФ:
  параметры (279), МКБ-10 полностью (15038) и урологический срез (553), классификации/шкалы,
  препараты МНН (3307) и бренды (4113), компоненты (7705), группы аллергий (124), перекрёстные
  реакции (70), скрытые аллергены (44), фенотипы (41), ЕСКЛП (7563) и др. Полный дамп каждого
  листа — в `reference/full/` (формат columns/rows), карта — `reference/manifest.json`.
- Тесты: `cd backend && python -m pytest -q` (страховочная сетка перед рефакторингом).

## Что это за репозиторий

Рабочий каркас реального проекта (не прототип): настоящий бэкенд (FastAPI + БД),
настоящий фронт (React + Vite), реальное API. AI-части (распознавание документов,
речь-в-текст, разбор естественного языка) вынесены в подключаемые интерфейсы
с рабочими заглушками — реальные модели встают туда после выбора AI-контура
под 152-ФЗ, не меняя структуру.

## Структура

```
second-memory/
├── backend/            FastAPI + SQLModel (dev: SQLite → prod: PostgreSQL)
│   └── app/
│       ├── models.py        доменная модель (пациенты, наблюдения-ряды, аудит…)
│       ├── routers/         API: пациенты, клиника, задачи, приём, дашборд, протокол
│       └── services/        OCR, STT, NLP, проверка аллергий (интерфейсы+заглушки)
├── admin/              Отдельная админ-панель (аналитика + поддержка), самостоятельный HTML
└── frontend/           React + Vite (mobile-first + десктоп, PWA-ready)
    └── src/
        ├── pages/           Главная, Неделя, Пациенты, Карточка, Задачи, Ещё…
        └── components/      Layout, VoiceButton, ProtocolTab
```

## Запуск

Нужны Python 3.11+ и Node 18+.

### 1. Бэкенд
```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m app.seed            # демо-данные (1 врач, 3 пациента, приёмы, задачи)
uvicorn app.main:app --reload # http://localhost:8000  (docs: /docs)
```

### 2. Фронтенд (в отдельном терминале)
```bash
cd frontend
npm install
npm run dev                   # http://localhost:5173
```
Запросы `/api/*` фронт проксирует на бэкенд (см. `vite.config.js`).

**Как посмотреть данные.** На экране входа есть кнопка **«Посмотреть демо (готовые данные)»** —
она пускает под демо-врача и, если база пустая, сама её заполняет (пациенты, приёмы, история).
Обычная регистрация создаёт **пустой** аккаунт (у нового врача своих данных ещё нет) — это
нормально; чтобы увидеть наполнение, используйте демо-вход или войдите как
`doctor@demo.ru` / `demo12345` (код придёт как «Демо-код» прямо на экране).

БД подключается через `DATABASE_URL` (по умолчанию SQLite-файл рядом с бэкендом;
для боевого — PostgreSQL). Таблицы создаются автоматически при старте.

## Что уже работает

- **Главная (дашборд)**: сводка дня (приёмы / просрочено / на проверке), умный
  голосовой захват («карманный диктофон» — записал, распознали, создали задачу),
  быстрый ввод текстом, подсказки в духе Toki («у N пациентов PSA выше порога»),
  и календарь-месяц прямо на главной.
- **Вкладка «Календарь»** (между Главной и Пациентами): детальный месяц с полосками
  приёмов по дням, выбор дня с агендой, переход в неделю; на выбранной дате — кнопки
  **«Начать приём»** (сразу новый пациент → карточка) и **«Новая запись»** (экран с
  вкладками «Новый пациент» / «Из картотеки» и временем приёма).
- **Цветовое разделение**: приём — синий, напоминание — фиолетовый (в календаре,
  на главной, в задачах).
- **Календарь месяц → неделя → день**: тап по неделе — подробный вид с полосой дней
  и переключением недель.
- **Десктопная раскладка**: боковое меню вместо нижних вкладок, контент шире.
- Пациенты: список, поиск (имя/диагноз), создание.
- Динамика показателей «было → стало» (наблюдения = временной ряд).
- Срез по картотеке (диагноз + порог показателя + возраст).
- Блок безопасности (3 состояния на пункт).
- Назначения с проверкой аллергий (не блокирует, требует причину, пишет в журнал).
- **Задачи (Todoist/Toki)**: естественный язык и голос; понимает срок, повтор,
  приоритет, метки и **раздел через первый #тег**; группировка по разделам и по датам;
  «отложить», выполнение, авто-создание следующего вхождения у повторяющихся.
- **Агент команд (голос/текст)**: одна строка или диктовка — сами определяем, что это:
  запись на приём («запиши Иванова на среду 15:00»), задача («заехать в магазин вечером»),
  заметка или запись в карту пациента («в карту Иванова: жалобы на никтурию»). На главной
  голосовой захват идёт через агента (services/assistant.py); провайдер ИИ переключается
  переменной AI_PROVIDER (stub → yandex → gigachat).
- **Распознавание с очисткой фото**: после OCR храним ТОЛЬКО распознанный текст,
  изображение не сохраняем (image_purged) — экономия места и меньше ПДн.
- **Импорт календаря из CSV**: «Ещё → Импорт календаря из CSV» (шаблон:
  GET /api/calendar/import/template).
- **Аналитика + админ-панель**: обезличенные события (POST /api/analytics/event),
  сводка для админа (GET /api/admin/analytics/summary, заголовок X-Admin-Token).
- **Триггеры (Toki-style)**: сохранённое условие слежения (создаётся из «Поиск →
  Срез по картотеке»); при запуске сам заводит контроль для подходящих пациентов
  (без дублей). Управление — «Ещё → Автослежение».
- **Недельная сводка** на главной: приёмы недели, контроли, просроченные.
- **Эскалация**: чем дольше просрочено напоминание, тем заметнее подсказка на главной.
- Голосовые заметки и протокол осмотра (поля как в ЕМИАС, копирование по блокам).
- Загрузка документа → OCR → значения «ожидают подтверждения».
- Защита №1 (сверка ФИО/ДР) и №2 (продолжить приём/новый).
- Тёмная/светлая тема.

- **152-ФЗ (реализуемое в коде уже сейчас)**: согласие пациента на обработку
  (получить/отозвать), журнал доступа к ПДн (AccessLog), экспорт всех данных
  пациента (право субъекта), удаление данных пациента с записью в аудит.
  Блок «Данные и согласие (152-ФЗ)» — в карте пациента.
- **Поддержка (чат)**: «Ещё → Написать в поддержку». Одно открытое обращение,
  закрытые — в истории; стороны различаются флагом from_staff, есть непрочитанные.
- **Отдельная админ-панель** (`admin/index.html`, открывается в браузере): аналитика
  использования + переписка поддержки (ответ/закрытие). Доступ по admin-токену.

Следующие шаги и отложенные решения — см. `docs/ROADMAP.md`.
